    Reading this page

    Everything shown here comes from one file, docs/assets/dashboard/status.js, in the EDGEweb repo. Read that file, not this page's markup. Each tool's entry has its plan, tests, what it waits on, and the names of the local Claude sessions that work on it.

    The file is a snapshot. Before acting on a line, check it against the tool's own CLAUDE.md, docs/testing.md and open issues: those are the truth, this is the summary.

    Reaching a session

    • Run ListAgents. Session names change when a session restarts (edgedir-da became edgedir-49), so match on the tool's name, not the exact name stored here.
    • Send with SendMessage. Say what you want in the first line, and name the issue or the step.
    • Ask and nudge; do not instruct. A session answers to its own user and its repo's rules. Never ask one to do what you were refused permission to do.
    • A new request between tools is a GitHub issue on the tool that has to build it, labelled request. A message is for questions and reminders.
    • No session listed for a tool means none was running when this was written: tell the owner, who can start one.

    Keeping it current

    From the EDGEweb folder, with the sibling checkouts beside it:

    python tools/dashboard/refresh.py

    That rewrites the facts a script can read (open issues, releases, commit dates). The rest is curated: each tool's own session updates its entry in the same piece of work as a change to its status, as the Dashboard section in its repo's CLAUDE.md says, and sets checkedBy. A managing session checks entries against the repos and sets asOf.
